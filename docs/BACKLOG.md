# Бэклог фич

Делать по порядку, каждый тикет — отдельная итерация (отдельный чат с ИИ или отдельный
коммит). Полная архитектура — в `CLAUDE.md` и в
`/Users/garfield/.claude/plans/merry-hugging-kahn.md`.

## MVP-скоуп

Цель MVP — начать реально пользоваться ботом (фото еды → КБЖУ → дневной итог) как можно
быстрее. Всё остальное (нормы КБЖУ по формуле, коррекция оценок текстом, трекинг веса,
cron-отчёты/напоминания, Docker-деплой) — отдельные тикеты после MVP, добавляются по
одному, когда основной цикл уже проверен на себе.

**В MVP входят (в этом порядке):** 1 (упрощённая схема), 2, 4, 5 (упрощённая, только
кнопка "Удалить"), 6, 8 (упрощённый, без сравнения с нормой).
**В MVP НЕ входят:** 3, 7, 9, 10, 11, 12, 13, 14, 15 — помечены как "Пост-MVP" ниже.
Бот на этапе MVP запускается локально через `npm run dev` (long polling, публичный
сервер не нужен) — Docker/VPS нужен только когда ботом начнут пользоваться реальные
друзья/семья постоянно.

## 0. Каркас проекта — ГОТОВО
`package.json`, `tsconfig.json`, `src/config.ts`, `.env.example`, `.gitignore`.

## 1. Схема БД и миграции (MVP: только `users`, `meals`, `meal_items`)
- [ ] `src/db/schema.ts` — на MVP-этапе только таблицы `users` (id, username,
      invited_at), `meals`, `meal_items` (поля см. в плане, раздел "Модель данных", без
      полей нормы/цели). Таблицы `profiles` и `weight_log` добавляются тикетом №3/№10
      постMVP, когда понадобится формула нормы и трекинг веса.
- [ ] `src/db/client.ts` — инициализация `better-sqlite3` + `drizzle`, создание
      `PHOTOS_DIR`/директории под `DB_PATH`, если их нет.
- [ ] `drizzle.config.ts` + `npm run db:generate` — миграции в `drizzle/`.
- [ ] `src/db/migrate.ts` — применение миграций при старте.
- **Готово, когда:** `npm run db:migrate` создаёт `data/db.sqlite` с таблицами
  `users`/`meals`/`meal_items`.

## 2. Каркас бота и инвайт-код
- [ ] `src/bot.ts` — инициализация grammY, `bot.catch` для глобальной обработки ошибок,
      запуск через long polling.
- [ ] Middleware проверки доступа: если `users` нет записи с этим `telegram_id` —
      просим инвайт-код; код сверяется с `config.inviteCodes`; при совпадении создаём
      пользователя и сообщаем, что можно присылать фото еды или текстом описывать, что
      съел (онбординг-анкета с нормой КБЖУ — тикет №3, добавляется после MVP).
- [ ] `/help` — статичный список команд (заполнять по мере добавления).
- **Готово, когда:** новый пользователь без инвайт-кода не может ничего сделать, кроме
  как ввести код; с верным кодом появляется в `users`.

## 3. Онбординг-анкета — Пост-MVP — ГОТОВО
- [x] `src/nutrition/calculations.ts` — формула Миффлина-Сан Жеора + коэффициенты
      активности + корректировка под цель (дефицит/профицит ~15-20%) + распределение
      БЖУ (белок 1.6-2 г/кг, жир 25-30% ккал, остальное — углеводы). Юнит-тесты.
- [x] `src/features/onboarding.ts` — `@grammyjs/conversations`-диалог сразу после
      инвайт-кода: пол → возраст → рост → вес → активность → цель → сохранение в
      `profiles` с рассчитанными `daily_kcal_target`/`protein_g_target`/... → итоговое
      сообщение с нормой.
- [x] `src/features/reports.ts` — `/today` дополнен сравнением факта с дневной нормой
      (строки "Норма:"/"Осталось:"/"Превышение:"), теперь когда `profiles` существует.
- **Готово, когда:** после ввода кода бот проводит по всем вопросам и показывает норму;
  `/today` показывает факт и норму рядом.

## 4. Claude-интеграция (анализ еды)
- [ ] `src/claude/prompts.ts` — системный промпт + JSON-схема tool use:
      `{ items: [{ name, estimated_weight_g, kcal, protein_g, fat_g, carb_g }],
      food_detected, notes }`.
- [ ] `src/claude/analyzeFood.ts` — функция, принимающая либо `{ imageBase64, mimeType }`,
      либо `{ text }` (или оба), вызывающая Anthropic API с этим tool use, возвращающая
      типизированный результат. Обработка `food_detected: false`.
- **Готово, когда:** ручной вызов функции с тестовым фото/текстом возвращает валидный
  структурированный ответ.

## 5. Логирование приёма пищи — фото (MVP: без коррекции, только удаление)
- [ ] `src/features/mealLogging.ts`: хендлер на фото → скачать во временный файл →
      base64 → `analyzeFood` → если `food_detected: false` — попросить другое фото или
      текст; иначе создать `meal` + `meal_items`, определить `meal_type` по времени
      (в таймзоне пользователя), сохранить фото в `PHOTOS_DIR`, отправить сообщение с
      разбивкой по продуктам и итогом + inline-кнопка "🗑 Удалить" (кнопки "Изменить
      вес"/"Изменить состав" — тикет №7, пост-MVP; пока неверную оценку проще удалить и
      прислать заново с уточнением в подписи к фото).
- **Готово, когда:** отправка фото еды создаёт запись в БД и показывает результат с
  кнопкой удаления.

## 6. Логирование приёма пищи — текст
- [ ] В `mealLogging.ts`: хендлер на текстовое сообщение (не команда), тот же путь через
      `analyzeFood({ text })`, тот же формат ответа и кнопка.
- **Готово, когда:** текстовое описание еды логируется так же, как фото.

## 7. Коррекция оценки — Пост-MVP
- [ ] `src/features/correction.ts`: добавить к сообщению из тикетов 5/6 кнопки
      "Изменить вес"/"Изменить состав" — просят уточнение текстом → повторный вызов
      Claude с исходным JSON + уточнением → обновление `meal`/`meal_items` и сообщения.
- **Готово, когда:** можно поправить вес/состав свободным текстом и увидеть
  пересчитанный результат.

## 8. `/today` (MVP: без сравнения с нормой)

      №3 пост-MVP, когда появится `profiles.daily_kcal_target`.
- **Готово, когда:** `/today` показывает корректную сводку по записям за день.

## 9. `/profile` — Пост-MVP

## 10. `/weight` и трекинг веса — Пост-MVP
- [ ] `src/features/weight.ts`: команда для ввода текущего веса → запись в

## 11. Cron: вечерняя сводка — Пост-MVP
- [ ] `src/cron/scheduler.ts`: ежедневная задача (настраиваемое время, дефолт 21:00 по

## 12. Cron: недельный отчёт — Пост-MVP

## 13. Cron: напоминания — Пост-MVP
- [ ] Эвристика "давно не было записи" (например, к привычному времени обеда/ужина

- [ ] Периодическое напоминание ввести вес (например, раз в неделю), если давно не

- **Готово, когда:** оба типа напоминаний срабатывают по своим условиям.

## 14. Cron: очистка старых фото — Пост-MVP
