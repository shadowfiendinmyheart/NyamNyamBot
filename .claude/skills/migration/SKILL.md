# Миграция схемы БД

Задача: `$ARGUMENTS`

Файлы в `drizzle/` (SQL и `meta/*`) генерирует только drizzle-kit — хук запрещает их
править вручную. Источник правды — `src/db/schema.ts`.

## Шаги

1. **Схема.** Изменить `src/db/schema.ts`. Следовать стилю существующих таблиц:
   - время — `integer(..., { mode: "timestamp" })` / как в соседних таблицах, хранится в UTC;
   - ккал — целые, БЖУ — real;
   - внешние ключи на `users` — как у существующих таблиц.

2. **Генерация.**
   ```bash
   npm run db:generate
   ```
   Если drizzle-kit задаёт интерактивный вопрос (переименование колонки/таблицы vs
   удаление+создание) — команда зависнет в неинтерактивном режиме. Тогда остановиться
   и попросить пользователя выполнить `! npm run db:generate` самому, объяснив, какой
   вариант выбрать.

3. **Проверка SQL.** Открыть новый файл `drizzle/NNNN_*.sql` и убедиться, что:
   - нет неожиданных `DROP TABLE` / `DROP COLUMN` (SQLite при изменении колонки
     пересоздаёт таблицу через `__new_*` — это нормально, но данные должны копироваться
     `INSERT INTO ... SELECT`);
   - у новых `NOT NULL`-колонок в существующих таблицах есть `DEFAULT`, иначе миграция
     упадёт на непустой БД.
   Если что-то не так — исправлять `schema.ts` и генерировать заново (удалив только что
   созданную миграцию через `git checkout -- drizzle && git clean -fd drizzle`).

4. **Применение локально.**
   ```bash
   npm run db:migrate
   ```

5. **Код и тесты.** Обновить запросы/типы, которые используют изменённые таблицы,
   затем `npm run build && npm test`.

6. Сообщить пользователю: имя файла миграции и короткое описание SQL (что добавлено/
   изменено). Напомнить, что на VPS миграция применится при старте контейнера.
