# Автопилот по бэклогу

Аргумент: `$ARGUMENTS` — необязательно: число (максимум тикетов за прогон) и/или фильтр
(тема, приоритет, номера тикетов), как у `/backlog`. Пусто — без лимита, все открытые.

`/clear` модель вызвать не может, поэтому «чистый контекст» на каждый тикет — это
**отдельный субагент** (Agent tool, `subagent_type: "general-purpose"`): он стартует
с пустым окном, делает тикет и возвращает короткий итог. Основной сеанс только
оркестрирует — сам код не читает и не пишет, чтобы его контекст не разрастался.

**Файл состояния** `.claude/fuck-tokens.json` (в `.gitignore`) — номер тикета, который
сейчас в работе: `{"ticket": N, "startedAt": "<ISO-время>"}`. Пишется перед запуском
субагента, удаляется только после проверки результата (шаг 3). Если он есть на старте —
предыдущий прогон оборвался посреди тикета N.

## 0. Предстартовая проверка и возобновление
- Ветка — `master`.
- Прочитать `.claude/fuck-tokens.json` и `git status`:
  - **Файла нет, дерево чистое** → шаг 1.
  - **Файла нет, дерево грязное** → остановиться: это чужие изменения, автопилот их
    не трогает. Показать `git status` пользователю.
  - **Файл есть (тикет N)** → прерванный тикет. Сообщить пользователю одной строкой
    «Возобновляю тикет N, прерванный <startedAt>» и выполнить шаг 2 для N с
    **промптом возобновления** (ниже). Лимит из `$ARGUMENTS` его не считает.

## 1. Выбрать следующий тикет
Прочитать `.claude/skills/backlog/SKILL.md` и применить его разделы 1–2 (сбор состояния
и ранжирование) к `docs/BACKLOG.md` с учётом фильтра из `$ARGUMENTS`. Взять **один**
тикет — первый рекомендованный. Вопрос «Запустить `/ticket N`?» не задавать.

Пропускать тикеты, которые в этом прогоне уже были помечены как «заблокирован».
Открытых тикетов не осталось или достигнут лимит → перейти к шагу 4.

## 2. Выполнить тикет в свежем субагенте
Записать `.claude/fuck-tokens.json` с номером N (если его ещё нет). Затем запустить
Agent (`general-purpose`, `description`: «Ticket N: <кратко>») с промптом:

> Ты работаешь в репозитории `C:\workSpace\nyamBot\NyamNyamBot`. Прочитай
> `.claude/skills/ticket/SKILL.md` и `CLAUDE.md` и выполни скилл `/ticket N` целиком
> (реализация, build+test, отметка в бэклоге, CLAUDE.md, коммит `[N] …` в master,
> code-review уровня high через Skill tool и коммит `[N] fix review findings: …` при
> необходимости). Ты работаешь в автономном режиме, пользователя нет:
> - шаг «задать вопрос пользователю» заменён на: если тикет неоднозначен или требует
>   решения пользователя (продуктового выбора, интерактивного `npm run db:generate`,
>   внешних ключей/доступов) — ничего не коммить, откати свои правки
>   (`git checkout -- . && git clean -fd`, только если изменения твои) и верни
>   `STATUS: BLOCKED` с причиной;
> - шаг 9 (предложить следующий тикет) пропусти;
> - не пушь; файл `.claude/fuck-tokens.json` не трогай.
> В конце верни ровно такой блок:
> ```
> STATUS: DONE | BLOCKED | FAILED
> TICKET: N
> COMMITS: <хеши через пробел>
> TESTS: <кратко: сколько тестов, зелёные ли>
> REVIEW: <исправлено X / отклонено Y>
> NOTES: <1–3 строки: что сделано или почему не вышло; как проверить в боте>
> ```

**Промпт возобновления** (для шага 0) — тот же, но первый абзац заменить на:

> Ты работаешь в репозитории `C:\workSpace\nyamBot\NyamNyamBot`. Тикет N уже начинали
> по скиллу `/ticket` (`.claude/skills/ticket/SKILL.md`, прочитай его и `CLAUDE.md`),
> но работа оборвалась на середине. Определи по `git status`, `git diff` и
> `git log --oneline -10`, где остановились, и доведи тикет до конца с этого места:
> - нет коммита `[N] …` → незакоммиченные правки — это частичная реализация тикета N:
>   сверь их с тикетом в `docs/BACKLOG.md`, доделай недостающее и продолжай с шага 3
>   (build+test) по шаг 7 включительно;
> - коммит `[N] …` есть, коммита `[N] fix review findings` нет → code-review по
>   мог не пройти до конца: выполни шаг 7 на коммитах тикета (`[N]`-коммиты
>   от первого до HEAD); незакоммиченные правки поверх — это начатые фиксы ревью,
>   проверь их и учти;
> - есть `[N] fix review findings` и дерево чистое → тикет уже завершён, просто
>   верни `STATUS: DONE` с хешами.

Дождаться завершения субагента (уведомления о его окончании) — не запускать следующий
параллельно: тикеты коммитят в один `master`.

## 3. Проверить результат и решить, идти ли дальше
- `git status` и `git log --oneline -3`: дерево чистое (кроме игнорируемого файла
  состояния), коммиты `[N]` на месте.
- Записать итог тикета (одна строка) в свой список.
- `DONE` + чистое дерево → удалить `.claude/fuck-tokens.json`, вернуться к шагу 1.
- `BLOCKED` + чистое дерево → удалить `.claude/fuck-tokens.json`, пометить тикет
  заблокированным на этот прогон, вернуться к шагу 1.
- `FAILED`, грязное дерево, не прошедшие build/test или неожиданный формат ответа →
  **остановиться**, файл состояния **оставить** (следующий запуск `/fuck-tokens`
  попробует возобновить этот тикет), ничего не откатывать сверх того, что сделал
  субагент, и перейти к шагу 4 — чинить вслепую следующими тикетами нельзя.

## 4. Итог пользователю
Коротко, по-русски:
- таблица: тикет · статус · коммиты · тесты · ревью;
- заблокированные тикеты — с причиной и вопросом, который нужно решить пользователю;
- если остановились на ошибке — что сломалось, состояние дерева и что файл состояния
  оставлен: повторный `/fuck-tokens` возобновит тикет N, а чтобы отказаться от него —
  откатить правки и удалить `.claude/fuck-tokens.json`;
- сколько открытых тикетов осталось.
Не пушить.
