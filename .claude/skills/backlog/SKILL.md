# Обзор бэклога и следующие задачи

Аргумент: `$ARGUMENTS` — необязательный фильтр (тема, приоритет, номер тикета). Если
задан — сузить рекомендации до подходящих тикетов.

Скилл ничего не реализует и не коммитит — только читает и предлагает.

## 1. Собрать состояние
- Прочитать `docs/BACKLOG.md` целиком. Открытый тикет — заголовок `## N. …` без
  «ГОТОВО» / «ОТМЕНЕНО» и с хотя бы одним `- [ ]`. Частично сделанный — есть и `- [x]`,
  и `- [ ]`.
- Для тикетов с номерами находок (`P0: 4`, `P1: 6` …) — заглянуть в `docs/UX_AUDIT.md`,
  чтобы понять суть и вес проблемы.
- `git log --oneline -15` — что делалось последним (коммиты с префиксом `[N]`); если
  последний тикет закоммичен без `fix review findings` — это нормально, не считать
  незавершённым.
- `git status` — если есть незакоммиченные изменения по какому-то тикету, упомянуть это
  первым: сначала стоит довести его.

## 2. Выбрать, что делать дальше
Ранжировать открытые тикеты по:
1. **Приоритет** — P0 раньше P1, P1 раньше P2 (по меткам в заголовке; тикет со
   смешанными метками — по самой высокой).
2. **Зависимости** — тикет, на который опираются другие, раньше (например, таймзона
   пользователя нужна для записей задним числом и для настроек уведомлений; миграции
   схемы лучше не размазывать по параллельным тикетам). Зависимости выводить из текста
   тикетов и кода, а не придумывать.
3. **Размер и риск** — при равном приоритете меньший / менее рискованный тикет раньше.
4. **Порядок в файле** — как последний критерий.

Если формулировка тикета расходится с текущим кодом (часть уже сделана, файл/модуль
называется иначе) — коротко проверить по коду (Grep/Read) и отметить это в выводе.

## 3. Ответ пользователю
Коротко, по-русски:

- **Прогресс:** «Сделано X из Y тикетов, открыто Z» (ОТМЕНЕНО не считать открытыми).
- **Рекомендую дальше** — 2–3 тикета по порядку, для каждого:
  - `N. Название` (приоритет) — суть в 1–2 строки;
  - почему сейчас (приоритет / разблокирует другие / быстрый);
  - заметки: нужна миграция, затрагивает ИИ-промпты, частично уже сделано и т.п.
- **Остальные открытые** — одной строкой каждый: `N. Название (приоритет)`.
- Если в бэклоге нашлись проблемы (тикет без «Готово, когда», устаревшие пункты,
  сделанное, но не отмеченное) — перечислить в конце, ничего не правя.

Закончить вопросом: «Запустить `/ticket N`?» с номером первого рекомендованного. Самому
не начинать. Если открытых тикетов нет — сказать, что бэклог пуст, и предложить
сформулировать новые (например, из `docs/UX_AUDIT.md`, если там есть находки без тикета).
